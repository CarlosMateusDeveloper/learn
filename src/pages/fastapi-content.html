1.1

Como o FastAPI funciona

O FastAPI não faz tudo sozinho — ele é montado sobre duas peças:

Starlette cuida da parte "web": receber requisições, encontrar a rota certa, devolver respostas. Pydantic cuida da parte "dados": conferir se o que chegou tem o formato certo.

E qual é a mágica que o FastAPI adiciona por cima? Ele lê a assinatura das suas funções — os tipos que você declara — e monta tudo a partir dela. Olhe:

@app.get("/items/{item_id}")
async def read_item(item_id: int, q: str | None = None):
    ...

Só de olhar essa função, o FastAPI conclui três coisas: item_id está na URL e precisa ser um número — se alguém acessar /items/abc, ele recusa sozinho, sem nenhum if seu; q não está na URL, então deve vir depois do ? e é opcional porque tem valor padrão; e tudo isso vira documentação automática na página /docs.

Fixe isso: a "leitura" das funções acontece uma vez só, quando o servidor liga — não a cada requisição. Se você errar a definição de uma rota, o erro aparece no startup, e não misteriosamente na primeira requisição de um usuário.
1.2

Cliente e servidor

Você já sabe o que é cliente e servidor — o que interessa aqui é onde o FastAPI se encaixa nessa conversa. E tem um detalhe que surpreende: o FastAPI nunca fala com o cliente diretamente. O caminho real é:

cliente  →  Uvicorn (o servidor de verdade)  →  FastAPI (o seu código)  →  resposta de volta

O FastAPI nunca toca a rede. Quem atende a conexão é o Uvicorn (já vamos falar dele), que traduz o que chegou e entrega mastigado para o seu código. Duas consequências práticas:

Se a API estiver atrás de um proxy (nginx, load balancer), o "cliente" que o FastAPI enxerga é o proxy, não o usuário final — por isso existe a opção --proxy-headers no Uvicorn, que ensina o servidor a ler o IP verdadeiro do usuário nos cabeçalhos. E se você precisar do dado cru, exatamente como chegou, basta pedir o objeto Request na sua função (request: Request) — acesso a tudo, antes de qualquer validação.

1.3

Rotas e endpoints

Relembrando o vocabulário em uma linha: rota é o caminho (/clientes); endpoint é caminho + método (GET /clientes e POST /clientes são dois endpoints diferentes).

Cada vez que você escreve @app.get(...), o FastAPI guarda essa rota numa lista interna. E aqui mora uma pegadinha clássica: na hora de decidir qual rota atende uma requisição, ele percorre essa lista na ordem em que você declarou:

@app.get("/users/{user_id}")   # declarada primeiro
def buscar_usuario(user_id: str): ...

@app.get("/users/me")          # declarada depois — NUNCA será alcançada!
def meu_perfil(): ...

Quando alguém acessa /users/me, a primeira rota captura antes, entendendo "me" como se fosse um user_id.

Regra prática: rotas fixas antes de rotas com variáveis.

Outra ferramenta que você vai usar o curso inteiro: o APIRouter. Pense nele como uma "mini-aplicação" que agrupa rotas parecidas — você define o prefixo e as configurações uma vez, e todas as rotas do grupo herdam:

router = APIRouter(prefix="/clientes", tags=["clientes"])
# tudo que for registrado nesse router já começa com /clientes
1.4

Uvicorn

O Uvicorn é o servidor: o programa que de fato fica escutando a porta, aceitando conexões e repassando cada requisição para o seu código.

Analogia: o FastAPI é o cozinheiro, o Uvicorn é o atendente do balcão. O cozinheiro nunca fala com o cliente — o atendente recebe o pedido, leva pra cozinha e entrega o prato de volta.

O que vale saber sobre ele: instale com pip install "uvicorn[standard]" — o [standard] traz versões aceleradas dos componentes internos (um deles, o uvloop, deixa a parte assíncrona 2 a 4 vezes mais rápida, de graça, sem mudar nada no seu código). Um processo do Uvicorn usa um núcleo do processador — a máquina de produção tem 4 núcleos? Rode --workers 4 para criar 4 cópias e aproveitar tudo. E o --reload (reiniciar sozinho quando o código muda) é maravilhoso em desenvolvimento e proibido em produção: ele derruba e recria o processo a cada mudança de arquivo.

1.5

ASGI

Se o Uvicorn é o atendente e o FastAPI é o cozinheiro, o ASGI é o idioma que os dois combinaram falar. É um padrão — um contrato — que define exatamente como um servidor Python entrega requisições para um framework.

E o contrato é surpreendentemente pequeno. Uma aplicação ASGI é só uma função assíncrona com três parâmetros: scope (um dicionário com as informações da requisição), receive (uma função para receber o corpo) e send (uma função para enviar a resposta). Quer ver algo curioso? Isto é uma aplicação web completa, sem framework nenhum, que roda no Uvicorn do mesmo jeito que o FastAPI:

async def app_crua(scope, receive, send):
    await send({
        "type": "http.response.start",
        "status": 200,
        "headers": [(b"content-type", b"application/json")],
    })
    await send({"type": "http.response.body", "body": b'{"ok": true}'})

Você nunca vai escrever isso no dia a dia. Mas saber que o FastAPI, lá no fundo, é "só" uma função dessas explica coisas que vêm pela frente: por que peças de outros frameworks encaixam nele, e por que WebSockets e streaming funcionam nativamente.

Fixe isso: existia um padrão mais antigo, o WSGI (usado pelo Flask clássico), que só trabalhava de forma síncrona — um pedido por vez, esperando parado. O ASGI é a evolução dele para o mundo assíncrono. O "A" é de Asynchronous.
1.6

Starlette

Aqui vai um segredo que simplifica sua vida: o FastAPI é uma subclasse do Starlette — literalmente class FastAPI(Starlette) no código-fonte. O Starlette é um framework web menor e mais cru; o FastAPI herda tudo dele e adiciona a camada inteligente de validação e documentação. Na hora de procurar documentação ou entender um erro, ajuda saber de qual camada vem cada peça:

Herdado do StarletteAdicionado pelo FastAPI
Request e ResponseDepends (você conhece no Módulo 3)
Middlewares (código antes/depois de toda requisição)Validação automática pelos tipos
BackgroundTasks (tarefas depois da resposta — Módulo 4)response_model (filtro da resposta — Módulo 2)
WebSockets, arquivos estáticosAs páginas /docs e /redoc

Na prática: qualquer coisa compatível com Starlette funciona no FastAPI sem adaptação. Se um middleware de terceiros diz "para Starlette", pode usar.

1.7

async e await

Este é o tópico mais importante do módulo — é o que separa uma API rápida de uma API que trava sem ninguém entender por quê. Vamos com calma.

Uma função normal do Python, quando espera algo lento (uma consulta ao banco, uma chamada a outra API), espera parada. Uma função assíncrona (async def) consegue dizer: "vou esperar isso aqui, mas enquanto isso pode atender outras pessoas". O await é exatamente esse aviso.

No FastAPI, seus endpoints podem ser escritos dos dois jeitos — e os dois funcionam. Mas cada escolha tem uma consequência: com def comum, o FastAPI percebe e executa sua função numa linha de execução separada (uma thread) para não travar o resto — é a escolha segura. Com async def esperando coisas assíncronas, você tem o cenário ideal: espera sem travar ninguém. E com async def escondendo uma biblioteca bloqueante dentro... vem a armadilha:

# ❌ A ARMADILHA: async por fora, bloqueante por dentro — trava o servidor inteiro
@app.get("/lento")
async def lento():
    r = requests.get("https://api.externa.com")   # requests é bloqueante!
    return r.json()

# ✅ Opção segura: def comum — o FastAPI cuida de não travar
@app.get("/ok-1")
def ok_sync():
    r = requests.get("https://api.externa.com")
    return r.json()

# ✅ Opção ideal: async de ponta a ponta (httpx é o "requests assíncrono")
@app.get("/ok-2")
async def ok_async():
    async with httpx.AsyncClient() as client:
        r = await client.get("https://api.externa.com")
    return r.json()
Regra de bolso do curso inteiro: só escreva async def se tudo que a função espera puder receber await. Na dúvida, use def comum — ele nunca cai na armadilha.
1.8

Event loop

Falta conhecer quem administra essa dança de "espera aqui, atende ali". Esse administrador é o event loop (em bom português, "laço de eventos" — mas todo mundo usa o nome em inglês).

Analogia: um garçom num restaurante cheio. Ele anota o pedido da mesa 1 e leva à cozinha. Não fica parado olhando a comida ficar pronta — atende a mesa 2, depois a 3, e quando o prato da mesa 1 sai, ele volta. Um único garçom, dezenas de mesas, ninguém abandonado. Cada await é o momento em que o garçom larga uma espera e vai cuidar de outra mesa.

É por isso que um único processo aguenta milhares de conexões simultâneas. Mas a analogia também revela o perigo: o restaurante inteiro depende de um garçom só.

O perigo: se o garçom parar para descascar um saco de batatas (uma tarefa pesada, sem nenhum await), todas as mesas ficam sem atendimento. É a armadilha da seção 1.7 — e também o que acontece com um time.sleep(5) dentro de async def. O certo ali é await asyncio.sleep(5), que devolve o controle ao garçom durante a espera.

Um truque bônus para fechar: dentro de uma mesma requisição, dá para pedir várias coisas ao mesmo tempo — se cada busca leva 1 segundo, o total é ~1 segundo, não 3:

@app.get("/dashboard")
async def dashboard():
    # as três buscas acontecem em paralelo, não uma depois da outra
    vendas, estoque, clima = await asyncio.gather(
        buscar_vendas(), buscar_estoque(), buscar_clima()
    )
    return {"vendas": vendas, "estoque": estoque, "clima": clima}
1.9

Configurando o ambiente

python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install "fastapi[standard]"

O [standard] instala o kit completo: FastAPI + Uvicorn turbinado + utilitários (incluindo o httpx, que você acabou de conhecer).

Dica de quem já se queimou: congele as versões (pip freeze > requirements.txt) — FastAPI e Pydantic evoluem rápido, e "ontem funcionava" é um dos bugs mais chatos de investigar.
1.10

Estrutura inicial do projeto

Por enquanto, simples assim:

projeto/ ├── .venv/ ├── .env # configurações sensíveis — NUNCA vai pro git ├── requirements.txt └── app/ ├── __init__.py └── main.py
Regra que vale desde o primeiro dia e para sempre: o main.py só monta a aplicação (cria o app, registra as rotas). Lógica de negócio nunca mora nele. A estrutura cresce no Módulo 3.
1.11

Executando o servidor

# desenvolvimento (reinicia sozinho e mostra erros bonitos)
fastapi dev app/main.py

# o jeito clássico, equivalente
uvicorn app.main:app --reload

# produção: sem reload, vários workers (lembra? 1 worker = 1 núcleo)
uvicorn app.main:app --host 0.0.0.0 --workers 4
